# ÖMANKÖ Post Creator

Telegram-бот, который накатывает фирменную графику ÖMANKÖ на фотографии. Редактор присылает кадры, отвечает на несколько вопросов кнопками и получает готовые к публикации файлы.

Бот **ничего не публикует сам** — он не подключён к каналам и не имеет там прав. Это рендер-инструмент, заменяющий ручную работу дизайнера по накатыванию айдентики.

---

## Что он делает

Берёт сырое фото и возвращает его же с фирменной графикой: логотипом, хештегом, заголовком, градиентом. Логотип и хештег при этом **не белые** — их цвет вычисляется из самого кадра, чтобы графика выглядела частью фотографии, а не наклейкой поверх.

Четыре режима под разные типы контента:

| Режим | Что делает | На выходе |
| --- | --- | --- |
| **Брендинг** | логотип канала + хештег по углам | `1_N.jpg` |
| **Обложка** | заголовок поверх градиента | `cover_N_feed.jpg`, `cover_N_ig.jpg`, `cover_N_tg.jpg` |
| **Коллаборация** | строка `ÖMANKÖ × партнёр` внизу | `collab_N.jpg` |
| **STORE** | витрина товара 2000×2500 | `store_N.jpg` |

Обложка из **одного** фото делает **три** файла: пост в ленту, сторис Instagram и сторис Telegram.

## Каналы сети

`основа ÖMANKÖ` · `Ö NEWS` · `Ö BEAUTY` · `Ö MUSIC` · `Ö AGENCY` · `Ö GASTRO`

У каждого свой логотип и своя геометрия. Каналы без собственных ассетов работают на общем Ö.

## Как пользоваться

Всегда шли фото **файлом** (скрепка → Файл), а не картинкой — иначе Telegram пережмёт исходник. Фото можно слать пачкой: настройки применятся ко всем сразу.

```text
Брендинг      /start → режим → канал → фото → /done → формат → хештег
Обложка       /start → режим → канал → фото → /done → заголовок → формат → хештег → слайдер
Коллаборация  /start → режим → лого партнёра → фото → /done → формат
STORE         /start → режим → фото → /done → подпись → цвет
```

Форматы: `4:5`, `2:3`, `1:1`, `3:2`, `Адаптивный` (без кропа).

**Слайдер затемнения** в обложках показывает живое превью — крути, если заголовок тонет или градиент съел кадр. Дефолт «норма» подходит почти всегда.

**Логотип партнёра** для коллаборации: PNG, белый силуэт, прозрачный фон, обязательно файлом.

### Команды

| Команда | Кто | Что |
| --- | --- | --- |
| `/start` | все | начать заново |
| `/done` | все | закончить загрузку фото |
| `/cancel` | все | отменить |
| `/myid` | все, пока не задан `ADMIN_ID` | узнать свой Telegram ID |
| `/stats` | админ и подписчики | сводка за 7 дней + карточка |
| `/broadcast` | админ | рассылка всем пользователям |
| `stats_on` / `stats_off` | по секрету | подписка на пятничный отчёт |

## Стек

```text
python-telegram-bot[job-queue]==20.7    # диалог + планировщик
Pillow==10.2.0                          # вся графика
pillow-avif-plugin==1.5.5               # AVIF с iPhone
numpy==1.26.4                           # яркость фона и градиенты
```

Python 3.11, Docker, Railway. Ни базы данных, ни веб-сервера, ни фронтенда. Один процесс `python bot.py`.

Extras `[job-queue]` обязателен — без него планировщик молча не запустится и пятничный отчёт не придёт.

Все логотипы — белые силуэты на прозрачном фоне. Белый цвет не используется: из файла берётся только альфа-канал, то есть форма. Цвет приходит из расчёта по фону.

### Навигация по `bot.py`

| Строки | Блок |
| --- | --- |
| 1–120 | импорты, состояния, выбор папки данных |
| 175–465 | статистика: текстовый отчёт и PNG-карточка |
| **468–645** | **все константы вёрстки — 90% правок здесь** |
| 649–800 | утилиты: цвет, яркость, шрифты, кэш |

Правило: всё, что можно подвинуть на макете, лежит в блоке 468–645. Менять вёрстку — значит менять числа там, а не лезть в функции рендера.

## Запуск

### Локально

```bash
pip install -r requirements.txt
export BOT_TOKEN="токен от @BotFather"
python bot.py
```

### Docker

```bash
docker build -t omanko-bot .
docker run -e BOT_TOKEN="..." omanko-bot
```

### Railway

1. New Project → Deploy from GitHub repo.
2. Variables → `BOT_TOKEN`.
3. **Volumes → Add Volume** — обязательно, иначе статистика и список пользователей обнулятся при следующем деплое. Mount path любой, бот подхватит сам.
4. Задеплоить, написать боту `/myid`, забрать ID.
5. Variables → `ADMIN_ID` → передеплой.
6. Проверить `/stats` — в хвосте должен быть зелёный маркер «постоянное (Railway Volume)».

### Переменные окружения

| Переменная | Обязательна | Что делает |
| --- | --- | --- |
| `BOT_TOKEN` | **да** | токен от @BotFather |
| `ADMIN_ID` | практически да | **пока не задан — `/stats` открыта всем**, рассылка не работает |
| `RAILWAY_VOLUME_MOUNT_PATH` | ставит Railway | признак постоянного хранилища |
| `STATS_SUBSCRIBE_CMD` | нет | имя скрытой команды подписки, дефолт `stats_on` |
| `STATS_UNSUBSCRIBE_CMD` | нет | дефолт `stats_off` |

## Данные

Три JSON-файла в папке, которую бот выбирает на старте:

| Файл | Что |
| --- | --- |
| `users.json` | все, кто жал `/start` — адресаты рассылки |
| `stats.json` | журнал событий: когда, канал, режим, сколько фото |
| `stats_subs.json` | подписчики пятничного отчёта |

Пишутся атомарно — во временный файл и `os.replace()`.

**Место выбирается по приоритету:** `RAILWAY_VOLUME_MOUNT_PATH` → `/data` → рядом с `bot.py`. Только первый вариант переживает деплой. Бот честно сообщает о проблеме в ответе на `/stats` и в логах при старте.

## Статистика

Каждый завершённый цикл дописывает одну строку в журнал. Никаких счётчиков — только факты, поэтому любой отчёт считается задним числом.

По пятницам в 19:00 МСК подписчикам уходит сводка: текст с разбивкой по каналам и режимам плюс PNG-карточка с барами по 8 неделям и двумя тепловыми картами (каналы × час дня, каналы × день недели).

## Известные проблемы

- **Коллаборации считаются как Брендинг.** `record_post()` не пропускает режим `collab` — он молча подменяется на `type1`. Отчёт врёт, историю не восстановить.
- **Обложка «2:3» на самом деле 3:4** (холст 1920×2560). В Брендинге та же кнопка даёт честные 1920×2880.
- **Нет лимита на размер пачки.** Достаточно жадная загрузка может упереться в память контейнера.
- **`Ö AGENCY` без своих логотипов** — работает на базовом Ö, ждёт макетов.
